# Test 3: Data / AI Validation Test

| Field | Value |
|---|---|
| **Objective** | Check that the matching feature puts the correct found item in the suggestions a student sees, meeting the success criterion in report §1.2: **Top-5 accuracy ≥ 50%**, every suggestion shows a percentage, and only suggestions of 20% or more are shown. |
| **Date** | 2026-10-08 (first run 2026-09-24, see "History" below) |
| **Environment** | Local machine, no AWS needed. Python 3 with the packages in `analytics/requirements.txt`. |
| **Dataset** | Synthetic, generated by `data/generate_dataset.py` (fixed seed 42): 105 lost reports, 105 found reports, 8 item categories. 85 lost reports have a true found counterpart; 20 deliberately have none. Ground truth in `data/ground_truth.csv`. See `data/README.md`. |
| **What is tested** | `analytics/match_items.py::get_matches()`, the exact function the web app calls through `src/inc/matching.php`, with the app's real settings: text = category + description + location, top 5 suggestions, 20% minimum score. |
| **Artefacts** | `analytics/match.py`, `analytics/match_items.py`, `data/lost_items.csv`, `data/found_items.csv`, `data/ground_truth.csv`, `evidence/test-data-ai-output.csv` |

## Steps

```bash
pip install -r analytics/requirements.txt
python3 data/generate_dataset.py   # optional: regenerates the committed CSVs (same seed, same data)
python3 analytics/match.py
```

## Expected result

- Top-5 accuracy ≥ 50% on the 85 lost reports that have a true match.
- Every suggestion has a score of 20% or more.
- Same output on every run (no randomness).

## Actual result (2026-10-08)

```
Loaded 105 lost items and 105 found items.
Settings: top 5 suggestions, minimum score 20%

--- PRODUCTION: category + description + location ---
Top-1 accuracy:                  34.1%  (29/85)
Top-3 accuracy:                  65.9%  (56/85)
Top-5 accuracy:                  89.4%  (76/85)
No-match items given a suggestion: 100.0%  (20/20)
Average suggestions shown:         4.97

--- BASELINE (before 2026-10-08): description only ---
Top-1 accuracy:                   8.2%  (7/85)
Top-3 accuracy:                  25.9%  (22/85)
Top-5 accuracy:                  35.3%  (30/85)
No-match items given a suggestion: 100.0%  (20/20)
Average suggestions shown:         4.44
```

Per-item detail (true match, its rank, all 5 suggestions with scores) is in `evidence/test-data-ai-output.csv`. Running the script twice gives a byte-identical CSV (MD5 `7a7935a7e0b1ad26b31716829e6ad1c7`), on both scikit-learn 1.6.1 and 1.8.0.

**Result: PASS.** Top-5 accuracy is 89.4%, well above the 50% target. All shown suggestions are ≥ 20% by construction (the same filter as `matches.php`).

## Interpretation

- **The feature is a triage aid, not an automatic decision.** The correct item is in the 5 suggestions 9 times out of 10, but is ranked first only about a third of the time. That fits the design: the student looks at up to 5 cards and claims the one that is really theirs, and Security then checks the claim against the finder's private detail before anything is released (`admin.php`).
- **Adding category and location tripled Top-1 accuracy and raised Top-5 from 35% to 89%.** Descriptions alone are short and generic ("black folding umbrella"), so many different items look identical. Category and location add the context that tells them apart.
- **Known weakness: items with no true match still get suggestions (20/20).** Same-category items share enough words to score above 20%, so the app always shows something. A threshold sweep (same script logic, production setting) shows no threshold fixes this without breaking the main target, because the score ranges overlap:

  | Minimum score | Top-5 accuracy | No-match items given a suggestion |
  |---|---|---|
  | 0.20 (app setting) | 89.4% | 20/20 |
  | 0.30 | 89.4% | 20/20 |
  | 0.40 | 85.9% | 20/20 |
  | 0.50 | 64.7% | 14/20 |
  | 0.60 | 41.2% (fails target) | 7/20 |
  | 0.70 | 21.2% (fails target) | 4/20 |

  0.20 was kept because it gives the highest Top-5 accuracy, and a wrong suggestion only costs the student a glance. This is acceptable only because no item is ever released on a suggestion alone; it is listed as a limitation in report §5.

## History: failed first run, diagnosis and fix

| Date | Setup | Result | Verdict |
|---|---|---|---|
| 2026-09-24 | Evaluation script used category + description + location, but scored only the single top suggestion at a 30% threshold. | Precision@1 32.9%, no-match items suggested 20/20 | Did not measure the stated Top-5 criterion. |
| 2026-10-08 | Re-checked the live app against the evaluation. Found the **app itself matched on description only**, so the 2026-09-24 numbers did not describe what users actually saw. Measured the real app behaviour first. | Top-5 35.3% | **FAIL** against the ≥ 50% target. |
| 2026-10-08 | **Fix:** app now matches on category + description + location (`src/inc/matching.php`), and `match.py` now evaluates the app's own `get_matches()` function at the app's own 20% threshold, so the test and the product can't drift apart again. | Top-5 89.4% | **PASS** |

A second bug was found and fixed at the same time: `matching.php` mapped scores back to found items by comparing description text, so if two found items had identical descriptions (common in practice, e.g. "black umbrella"), both scores were attached to the first one and the second item never appeared. Scores are now mapped by position in the list, which is always unique.

## Limitations and improvement plan

1. **Synthetic data.** Descriptions come from a small set of templates per category, so real reports (typos, abbreviations, richer detail) may score differently. Next step: collect a small, consented and anonymised sample of real reports from Security to re-run this test.
2. **No "no match" answer.** See interpretation above. Improvement: add date proximity (a found date before the lost date is impossible) as a filter, and show "no strong match yet" when the top score is not clearly ahead of the rest.
3. **Lexical only.** TF-IDF does not know that "flask" and "bottle" mean similar things unless they co-occur. Improvement: sentence embeddings (e.g. a small Sentence-BERT model), evaluated with this same script for a like-for-like comparison.
